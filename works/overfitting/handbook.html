五、三键机制白话图解

签名规则 R 有两层：签名物（事后布设，演戏挑衅）与目标选择函数（事前运行，决定谁死）。两层功能独立，但目标键的参数由签名物携带发布——松枝（和读者）因此误读为同一套规则。这个误读本身就是 overfit。

键 m（主键：谁进来）

  • 条件：m % 103 == 0。103 = nextprime(101)，101 是 E2 现场签名的当前质数项。
  • m 映射自学籍号（旧系统字段）。
  • 实算存档（truth §9）：白川 m=515（=103×5）、佐藤 m=721（=103×7）、候补 X m=1133（=103×11）——全部命中。
nextprime(101) -> 103          # 签名物 101 发布前瞻参数
for p in D:                    # 中村研究室轨道关联人员数据集
    if p.m % 103 == 0: S.add(p)

键 t（序键：谁先死）

  • 定义：候选人下一个已确定的学术关联日程（会议开幕/访问/截止），含已定但未发生的日程；t 升序 = 谁先死。
  • 这就是佐藤排 7/5 的原因：他转岗后仍被邀请研究室年会（7/5，周日），普通人的温情人脉成了排序字段。
  • 实算：白川 6/19（东京会议开幕）< 林 6/27（理事会）< 小島 7/2（筹备会）< 佐藤 7/5（年会）→ 第一次预测=白川（ch12）。
S.sort(key=lambda p: p.next_academic_event)   # 含未来日程
predict(S[0])  # -> 白川, 6/19

键 c（曲线键：E3 后的「精化」）

  • 来源：E3 白板上的曲线 y² = x³ + 2x + 3（定义在 F₉₇ 上） 与标记点 (20, 63)（实算：20³+2·20+3 ≡ 63² ≡ 89 mod 97，点确实在曲线上）。
  • 条件：c ≡ 63 (mod 97)，63 = 标记点 y 坐标；c 映射自转岗后的职员编号（与 m 不同字段）。
  • 实算存档：佐藤原始 c=548（548 % 97 = 63，满足）；编辑后 549（549 % 97 = 64，不满足）。白川 257、林 354、小島 451、候补 839——均 ≡ 63 mod 97。

548 → 549：一个字段一个单位如何挪走佐藤

四月清洗期，佐藤的职员编号在旧系统记 548、现属系统记 549（转岗迁移末位错一位，每个大学人事档案都有的脏数据）。早川「以现属系统为准」把 548 改成 549——两个都是真值，理由齐全，日志留痕，松枝当场目击并认可。四个月后的 8/5 夜，松枝建成曲线键；8/6 会议上，549 不落剩余类 → 「佐藤実，剔除，残差超限」→ 8/7 撤岗生效 → 8/8 夜死。

# 四月（编辑）              # 八月（精化 R）
sato.c: 548 -> 549         if sato.c % 97 == 63: keep
                           else: drop(sato)     # 549%97=64 -> 剔除
# 用原始值重算（ch22-23）：548%97=63 -> 佐藤从未出局

改动先于条件：四月动手的人必须已经知道八月会有一条模 97 的条件来读这个字段——知道这件事的只有设计条件的人。重读要点：松枝的错不在逻辑，在他用的数据集；而 c 键的引入（「标记点不是装饰，是新参数」）那种硬凑的勉强感，正是凶手设计好等他踩的 overfit 展示。
