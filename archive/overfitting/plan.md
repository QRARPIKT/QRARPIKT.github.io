- D5-1：机制三采用 G 的 b'（理论判「安全」的无辜者被杀）；细化为「死者曾符合签名、被凶手数据策展移出集合」→ 侦探的罪=信任了被策展的现实。（用户已认可）
- D5-2：Block 18 砍半接受——搭档零主动递框架，全书仅 2-3 次「不否定」式被动塑形。（用户已认可）

## 阶段规划

### Stage 1：元结构蓝图（当前阶段，用户最关心的先审）
产出：blueprint.md
- 读者状态曲线（逐章：读者信什么/疑什么/爽度不安度/与侦探信息差）
- 双重读法登记表（初读A义/重读B义/埋设/回收，修订受保护）
- 反转层进结构（四层解答各推翻什么、线索在哪层被重新定性）
- 案件序列与互锁锚点清单（≤8）vs 自包含项边界
- 批注相位表（5 相位，与正文事件对齐）
- 字数分配提案
**门禁：用户审过 → Stage 2**

### Stage 2：truth.md 主体
- **时间线精度原则（用户裁定）**：分钟级只给 E1 纽结手法与 A4b→A5 撤保护窗口；其余案件事件级。正文不 foreground 逐分钟推算（防中长篇读者疲劳），时间线用于自洽而非供读者核对
- **前置门禁**：动笔前先写一页「A4a→A4b 数学变换伪代码」（雏形 R 包含 b' → 精化 R 排除 b' + 目标排序规则：为何 ch12 第一次预测的目标是 E3 死者而非 b'），代码实算确认可行再展开
- 五起死亡的事件级/分钟级时间线（凶手视角真实版 + 认知版对照）
- 签名推算表（琼斯多项式/质数序列/椭圆曲线，全部代码实算，禁心算）
- b' 死者的数学排除理由（数据策展机制）
- 物理可行性清单（混合作案+雇人隔层，逐步耗时+失败模式）
- 线索台账 CL-xx（三态）+ 批注台账（表层读法/重读读法 25 条）
- 叙述纪律 + 修订记录 R-n
**门禁：机器校验（锚点代码复核）+ 双评审 swarm → 用户审**

### Stage 3：章节大纲（逐章 500-800 字功能卡）
**门禁：用户审**

### Stage 4：分章写作（fiction 纪律）
每批 1 个 writer（1-5 章）+ 并行双评审（逻辑/时间线 + 文风/读者状态曲线符合度）
+ 每批后跑 verify_probes.py 全套探针。WARNING/REVISE → 派 fix 子代理。
**每 2-3 批向用户汇报进度+关键样章**

**缓冲分配预算（R-2，G 提案采纳）**：总目标 ~14.2 万，20 万上限内 ~5.8 万缓冲，
每批写作只能从对应预算取字数，防止无序膨胀：
- L1 琼斯多项式推演（ch4-6）让读者「跟一遍」：+0.5 万
- ch15 谷值补偿（C 案粗粝 + 伊达戏 + C 的上岸意象）：+0.3 万
- ch22-23 冷段呼吸空间（发现策展 + 重演拟合）：+0.5 万
- ch24 自白上（批注 P5 + 对话并置，工程难度最高）：+0.5 万
- 终章两版试写：+0.2 万
- 不可预见预留：+1 万
预计使用 ~3 万，总量 ~17 万，仍在 20 万内。

### Stage 5：终幕特别处理
- 终章独白、结尾两版（微观动作 vs 叠加「我还不知道」）试写给用户选
- 全书可重读性核查（双重读法登记表逐条回溯验证）

### Stage 6：交付
合订本程序化组装 → 全套探针 → 字数实测回写 → docx 转换交付
