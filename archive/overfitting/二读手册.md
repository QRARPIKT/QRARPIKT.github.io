## 五、三键机制白话图解

签名规则 R 有两层：**签名物**（事后布设，演戏挑衅）与**目标选择函数**（事前运行，决定谁死）。两层功能独立，但目标键的参数由签名物携带发布——松枝（和读者）因此误读为同一套规则。**这个误读本身就是 overfit**。

### 键 m（主键：谁进来）

- 条件：`m % 165 == 0`。165 = E2 签名数列（3、7、21、49 = n 个交叉点下的素纽结数，OEIS A002863）的下一项 a(10)。
- m 映射自**学籍号**（三位旧档号，旧系统字段）。
- 实算存档：中村 m=165（=165×1，序列下一项即第一死者编号）、高野 m=990（=165×6）、白川 m=330、林 m=495、小島 m=660、佐藤 m=825——1000 以内 165 的倍数恰 6 个，全部命中。

- 白话：把数据集 D（中村研究室轨道关联人员）里每个人的学籍号除以 165，余数为 0 的进目标集合 S。参数 165 由上一案的签名数列向前发布（3、7、21、49 的下一项）——签名物不仅签名，还在发布下一把锁的钥匙。

### 键 t（序键：谁先死）

- 定义：候选人**下一个已确定的学术关联日程**（会议开幕/访问/截止），**含已定但未发生的日程**；t 升序 = 谁先死。
- 这就是佐藤排 7/5 的原因：他转岗后仍被邀请研究室年会（7/5，周日），普通人的温情人脉成了排序字段。
- 实算：白川 6/19（东京会议开幕）< 林 6/27（理事会）< 小島 7/2（筹备会）< 佐藤 7/5（年会）→ 第一次预测=白川（ch12）。

- 白话：把 S 里的人按「下一个学术日程」从早到晚排序，排最前的就是下一个目标。第一次排序的输出是白川（6/19）——这就是 ch12 第一次预测的来源。

### 键 c（曲线键：E3 后的「精化」）

- 来源：E3 白板上的曲线 **y² = x³ + 2x + 3（定义在 F₉₇ 上）** 与标记点 **(20, 63)**（实算：20³+2·20+3 ≡ 63² ≡ 89 mod 97，点确实在曲线上）。
- 条件：`c ≡ 63 (mod 97)`，63 = 标记点 y 坐标；c 映射自**转岗后的职员编号**（与 m 不同字段）。
- 实算存档：佐藤原始 c=548（548 % 97 = 63，**满足**）；编辑后 549（549 % 97 = 64，不满足）。白川 257、林 354、小島 451、候补 839——均 ≡ 63 mod 97。

### 548 → 549：一个字段一个单位如何挪走佐藤

四月清洗期，佐藤的职员编号在旧系统记 548、现属系统记 549（转岗迁移末位错一位，每个大学人事档案都有的脏数据）。早川「以现属系统为准」把 548 改成 549——两个都是真值，理由齐全，日志留痕，松枝当场目击并认可。四个月后的 8/5 夜，松枝建成曲线键；8/6 会议上，549 不落剩余类 → 「佐藤実，剔除，残差超限」→ 8/7 撤岗生效 → 8/8 夜死。

- 四月：编辑发生，548 → 549。
- 八月：549 ÷ 97 余 64，不等于 63 → 「残差超限」，剔除。
- 重算（ch22–23）：548 ÷ 97 余 63 → **佐藤从未出局**。

改动先于条件：四月动手的人必须已经知道八月会有一条模 97 的条件来读这个字段——知道这件事的只有设计条件的人。重读要点：松枝的错不在逻辑，在他用的数据集；而 c 键的引入（「标记点不是装饰，是新参数」）那种硬凑的勉强感，正是凶手设计好等他踩的 overfit 展示。
